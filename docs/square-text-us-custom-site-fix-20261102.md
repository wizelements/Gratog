# Taste of Gratitude: Square Text Us on a custom Vercel website

## Confirmed cause
The Square Messages **Website** toggle does not inject Square's native Text Us widget into an independently deployed Next.js/Vercel website, even when Square's **View site** opens `tasteofgratitude.shop`. Square documents its native button for Square Online, supported booking sites, invoices and other hosted transactional surfaces.

## Available now: no-SMS web messaging
- The site has its own **Message us** entry point, linked directly to the existing persisted contact form.
- After a multi-item nonmarket request succeeds, the customer can send a question against the exact saved order reference. The backend validates reference plus the request's matching email, applies rate limiting, atomically appends one bounded message, and sends a best-effort merchant alert.
- The authorized merchant inbox at `/admin/nonmarket-orders` displays those messages and provides a reply-by-email action.
- This does **not** create a Square Messages conversation, send a text, charge a customer or reserve product stock. Website contact is not deceptively labeled as Square SMS.

## Optional direct Square Messages texting (only after real verification)
Square offers a dedicated toll-free Messages business number to eligible paid subscribers. **Never invent a phone number or attach an unverified personal cellphone**.

1. In the merchant Square Dashboard, open **Messages → Settings → Your business number**.
2. Confirm the number is **verified** (claim it through Square if required; third-party carrier verification can take business days).
3. From a separate phone **text the exact business number**; confirm receipt and ability to reply in the intended Square location's Messages inbox. Confirm the sender number matches the business number, not a personal contact.
4. Configure these two **server-side** Vercel variables for the correct environment:
   - `SQUARE_MESSAGES_DEDICATED_NUMBER`: the verified Square toll-free E.164 number (for example `+18002345678` is a format illustration ONLY; never use it as a live number).
   - `SQUARE_MESSAGES_NUMBER_VERIFIED=true`: set only after the real text/reply test.
5. Redeploy the correct environment. The site then displays a native-device **Text us** action while retaining the **Website message** fallback. An order confirmation also includes the verified SMS deep link, prefilled with the order reference.
6. Perform an Android and iPhone manual end-to-end test. Verify the sent message actually lands in Square Messages and staff can send a payment link in that conversation.

Number and SMS gate are fail-closed: no confirmed E.164 U.S. Square toll-free number or no explicit verified flag = no website SMS action.

### Deployment permissions
The connected Vercel account was denied environment variable administration (HTTP 403). The owner or an authorized Vercel administrator must set those nonsecret configuration values in the intended project/environment. Do not bypass this access control or write credentials into GitHub.

## Final production certification evidence
- A saved website order request must have an exact matching merchant inbox entry.
- A separate customer-originated SMS must appear in the **correct Square Messages location**. Website inquiry alone does not prove Square SMS.
- A Square payment link generated by the authorized merchant must itemize the correct items/fees and be tied to the reference in staff workflow.
- Staff must verify actual Square payment status and refunds; **a screenshot, sent link, unpaid request or a message are not proof of payment**.
- Preserve market QR payment blocks until independent physical/Square stock reconciliation and payments certification are complete.

## Safe fallback
If the Square business number is unavailable, unverified, or the plan does not support it, keep using the website message form + authenticated merchant request inbox + email reply. Never silently fall back to Twilio or impersonate the native Square widget.
